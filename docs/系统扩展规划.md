# 单位内部信息管理系统 - 扩展规划

## 一、系统现状分析

### 已实现的核心功能
✅ **用户与权限管理**
- 三级权限体系（超管/单位管理员/普通用户）
- 单位组织架构（支持层级结构）
- 名单匹配注册机制
- 操作日志审计

✅ **人员信息管理**
- 完整的人员档案（基本信息、政治面貌、工作信息、学历、家庭等）
- 多段子表（家庭成员、学历经历、工作经历、奖惩记录）
- 自定义字段动态扩展
- 字段级变更历史追踪
- 身份证智能联动

✅ **报表生成**
- Excel 模板上传
- 智能字段匹配
- 自动填充生成报表

### 技术架构优势
- **后端**: FastAPI + SQLAlchemy（轻量、高性能、易扩展）
- **前端**: Vue 3 + Element Plus（现代化、组件丰富）
- **数据库**: SQLite/PostgreSQL（开发便捷、生产可靠）
- **权限设计**: 已有基础框架，易扩展到字段级

### 📅 第一阶段：核心基础增强（1-2个月）
**目标**: 构建完整的组织架构和精细化权限体系

#### 1.1 组织架构完善
```
新增模型：
- Department（部门）: 支持多级部门树
- Position（岗位）: 岗位字典 + 人数编制
- Rank（职级）: 职级体系（科员/副科/正科...）
- PersonPositionHistory（人员岗位历史）: 记录调动轨迹
```

**数据库设计**:
```python
class Department(Base):
    """部门表 - 多级树形结构"""
    id = Column(Integer, primary_key=True)
    unit_id = Column(Integer, ForeignKey("units.id"))
    parent_id = Column(Integer, ForeignKey("departments.id"))
    name = Column(String(100))
    code = Column(String(50))
    manager_id = Column(Integer, ForeignKey("persons.id"))  # 部门负责人
    level = Column(Integer)  # 层级深度
    sort = Column(Integer)   # 排序

class Position(Base):
    """岗位字典"""
    id = Column(Integer, primary_key=True)
    name = Column(String(100))
    code = Column(String(50))
    category = Column(String(50))  # 管理岗/技术岗/工勤岗
    rank_ids = Column(JSON)  # 可任职级列表
    is_active = Column(Boolean, default=True)

class PersonPosition(Base):
    """人员岗位信息（从Person表分离，支持历史记录）"""
    id = Column(Integer, primary_key=True)
    person_id = Column(Integer, ForeignKey("persons.id"))
    department_id = Column(Integer, ForeignKey("departments.id"))
    position_id = Column(Integer, ForeignKey("positions.id"))
    rank_id = Column(Integer, ForeignKey("ranks.id"))
    is_primary = Column(Boolean, default=True)  # 是否主岗位
    start_date = Column(Date)
    end_date = Column(Date, nullable=True)  # null表示当前在职
```

class WorkflowTemplate(Base):
    """流程模板"""
    id = Column(Integer, primary_key=True)

    id = Column(Integer, primary_key=True)
    template_id = Column(Integer, ForeignKey("workflow_templates.id"))
    applicant_id = Column(Integer, ForeignKey("users.id"))
    form_data = Column(JSON)  # 表单数据
    status = Column(String(20))  # draft/pending/approved/rejected
    current_node = Column(String(50))

class WorkflowNode(Base):
    """流程节点"""
    id = Column(Integer, primary_key=True)
    instance_id = Column(Integer, ForeignKey("workflow_instances.id"))
    node_key = Column(String(50))
    node_name = Column(String(100))
    handler_id = Column(Integer, ForeignKey("users.id"))

## 六、风险与建议

### 主要风险
1. **数据迁移风险**: 需要仔细规划从现有系统到新系统的数据迁移
2. **权限设计复杂度**: 细粒度权限容易过度设计，建议从简到繁
3. **流程引擎通用性**: 不同流程差异大，需要良好的抽象

### 建议
1. **敏捷开发**: 采用小步快跑的方式，每 2 周交付可用功能
2. **用户参与**: 让实际使用者参与需求确认和测试
3. **文档先行**: 先设计 API 文档和数据库设计，再编码
4. **自动化测试**: 为核心模块编写单元测试和集成测试
