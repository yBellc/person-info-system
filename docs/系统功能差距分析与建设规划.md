# 系统功能差距分析与建设规划
> 对比对象：泛微E-cology / 用友BIP HR / 钉钉专业版 / 飞书人事 / 北森一体化HR SaaS
> 适用场景：部门多、员工多、层级复杂的大型行政/企事业单位
> 文档日期：2026-08-11

---

## 一、总体评估

### 1.1 现有系统模块清单（已实现）

| 模块 | 子功能 | 实现状态 |
|------|--------|----------|
| **认证/权限** | 登录、注册、人事批量注册、首次改密、JWT、6种角色、数据权限/字段权限模型 | ✅ 基础可用 |
| **人员档案** | CRUD、家庭成员/教育/工作/奖惩、自定义字段、变更日志、Excel导入 | ✅ 基础可用 |
| **组织架构** | 单位树、部门、岗位、职级、人员岗位关系 | ✅ 基础可用 |
| **OA流程** | 4类固定流程模板、串行审批、同意/拒绝、撤回、审批时间轴 | ✅ 基础可用 |
| **工作台** | 通知公告（含已读标记）、待办事项、数量卡片 | ✅ 基础可用 |
| **统计报表** | 报表模板、统计接口 | ⚠️ 半完成（数据字段不够丰富） |
| **账号/名单管理** | 名单维护、批量创建、重置密码、启用停用 | ✅ 基础可用 |

### 1.2 总体差距定位

```
已实现  ≈  25%  (满足最小可用)
缺失但核心  ≈  45%  (大型单位必须、直接影响严谨性和合规性)
缺失但进阶  ≈  30%  (锦上添花、提高效率、体验)
```

如果直接在大型单位使用，现有系统存在 **审批链不够灵活、没有部门多层级联动、缺少操作审计细节、没有劳动合同/考勤/资产等核心业务数据支撑、没有消息推送** 等严重问题。下面分模块详细列出。

## 二、分模块差距分析

### 2.1 认证与账号安全（影响：安全基础是否扎实）

| 功能 | 现有 | 成熟系统标准 | 差距说明 |
|------|------|--------------|----------|
| 密码策略 | ❌ 无限制（6位即可） | 8位以上+大小写+数字+特殊字符；30/90天强制改密；不能用最近5次旧密码；密码强度校验 | 弱密码风险高，内网环境也可能被撞库 |
| 登录失败锁定 | ❌ 无 | 5次失败锁定账号30分钟/需要管理员解锁 | 防暴力破解必备 |
| 登录会话管理 | ❌ 无Token失效细节 | 支持强制下线、查看在线设备、单点登录SSO/LDAP/AD域对接 | 大单位一般和AD域联动，不能每个系统单独建账号 |
| 双因素认证(2FA) | ❌ 无 | 短信验证码/钉钉/企业微信扫码登录 | 管理员账号必须开启 |
| 登录日志 | ❌ 仅写入OperationLog，无独立模型 | 独立LoginLog表：IP、UA、地点、是否成功、失败原因、登录时间、登出时间 | 安全审计要求，出安全事故可追溯 |
| 账号密码传输 | ⚠️ 纯HTTPS即可（内网一般无HTTPS） | 密码前端RSA加密或HTTPS | 内网系统建议HTTPS，否则明文抓包可看到 |
| 操作审计日志 | ⚠️ 有OperationLog，但粒度粗 | 关键操作（删除/重置密码/改权限）必须记录：操作者、IP、时间、变更前后值JSON | 人事操作的审计是大型单位合规生命线，必须"谁在什么时间改了什么" |
| 数据脱敏 | ⚠️ 名单里有，列表里不一定全有 | 身份证/手机号默认脱敏，点击才显示，且记录"谁查看过完整身份证号" | 属于个人隐私合规要求 |
| 隐私协议+用户协议 | ❌ 没有 | 首次登录弹窗勾选同意；未同意不能使用 | 劳动法+个人信息保护法要求 |

### 2.2 组织架构管理（影响：部门多人多时是否不乱）

| 功能 | 现有 | 成熟系统标准 | 差距说明 |
|------|------|--------------|----------|
| 单位/部门多层级 | ⚠️ 只有Unit.parent_id，Department没有父级 | 支持N级部门树（总公司→分公司→中心→部→室→组），每一层级有完整的编制和负责人字段 | 大单位部门多，必须多级嵌套，不能只有单位+二级 |
| 部门编制管理 | ❌ 无 | 每个部门有"编制数/在编数/空缺数"，新增人员时超编自动预警 | 事业单位控编必须有 |
| 部门负责人/分管领导 | ❌ 无（没有Department.manager_id字段） | 部门上有部门负责人、分管领导、书记等多角色；审批时根据单据所属部门自动找到对应审批人 | **现有流程审批人是写死在模板的固定用户ID**，这是最大问题！部门多了根本维护不了 |
| 部门排序/分组 | ❌ 没有order字段 | 支持拖拽排序，显示顺序与正式发文一致 | |
| 岗位体系 | ⚠️ 只有Position名称 | 岗位类别（管理岗/专技岗/工勤岗）、岗位序列、岗位说明书、岗位编制 | 国企/事业单位岗位体系非常严谨，必须细化 |
| 职级体系 | ⚠️ 只有Rank名称 | 职级等级数字、对应工资档、晋升年限规则 | |
| 人事异动 | ❌ 无（没有晋升/调岗/调薪/离职流程） | 每一次异动走审批，生成异动单；人员档案自动更新；留下异动历史（可追溯） | 目前手动改信息，没有痕迹，审计风险 |
| 编制报表 | ❌ 无 | 按单位/部门统计编制/在岗/空缺、超编预警 | |

### 2.3 人员档案与人力资源管理（影响：HR核心业务是否完整）

| 功能 | 现有 | 成熟系统标准 | 差距说明 |
|------|------|--------------|----------|
| 档案字段完整度 | ⚠️ 50%左右 | 需补齐：政治面貌加入组织日期、转正日期、入本单位日期、首次参加工作日期(含知青/参军)、用工形式(在编/合同制/劳务派遣/外包)、人员类别(干部/工人)、行政级别(正处/副处等)、工资档次、入党日期、入民主党派日期、学位获取日期、专业技术职务、执业资格、外语水平、计算机水平、宗教信仰、血型、身高、健康状况、兵役情况、户籍地址、籍贯到省市区县、出生地到省市区县、现居住地详细地址、配偶单位及职务、父母及兄弟姐妹信息(完整亲属表) | 事业单位干部档案非常严谨，缺字段直接影响提拔/考核/调档 |
| 合同管理 | ❌ 无 | 劳动合同(起止日期/期限类型/签订次数)、聘用合同、试用期、合同到期前30/60天自动提醒、续签记录 | 劳动法要求，漏签双倍工资 |
| 试用期管理 | ❌ 无 | 试用期起止、转正审批流程、试用期考核 | |
| 入职/离职/退休流程 | ❌ 无 | 入职清单办理(门禁/邮箱/工位/社保)、离职交接清单审批(资产归还/工作交接)、退休前预警+退休审批 | 现有系统只有手动改数据，没有全流程 |
| 考勤管理 | ❌ 无 | 排班、打卡(GPS/WiFi/人脸)、请假关联考勤扣减、加班、调休余额、旷工自动记录 | 和请假流程关联，请假流程通过后自动扣年假余额 |
| 假期/余额管理 | ❌ 无（请假流程不扣余额） | 年假/病假/事假/婚假/产假/丧假/调休等余额，年初自动生成、跨年结转规则、超期作废 | **这是请假审批必须联动的**，不然重复请假余额就对不上 |
| 薪酬/工资条 | ❌ 无 | 薪资结构、社保公积金基数、个税计算、工资条发放(员工端查看) | |
| 绩效考核 | ❌ 无 | KPI/OKR/360度评估、考核等级(优秀/称职/基本称职/不称职)、与晋升/薪资联动 | |
| 招聘管理 | ❌ 无 | 需求审批→简历筛选→面试(多轮)→背景调查→体检→offer→入职 | |
| 培训管理 | ❌ 无 | 培训计划、课程、报名、签到、考核、学时记录、培训证书 | 事业单位有年度学时要求 |
| 证照/资格管理 | ❌ 无 | 专业证书(注册会计师/建造师等)、有效期、到期提醒、继续教育要求 | |
| 档案附件/扫描件 | ❌ 无（没有文件上传模型+OSS） | 身份证扫描件、学历证、学位证、合同扫描件、一寸照片，分类上传，权限控制 | 电子档案必备，大单位必须有 |
| 生日/入职周年/合同到期提醒 | ❌ 无 | 工作台自动提醒 + 邮件/站内信推送 | |
| 花名册导出模板 | ⚠️ 有基础导出 | 按《干部任免审批表》《干部基本信息表》等标准模板导出Word/PDF | 组织部/人事发文标准格式 |

### 2.4 OA流程引擎（影响：大单位审批是否严谨灵活）

| 功能 | 现有 | 成熟系统标准 | 差距说明 |
|------|------|--------------|----------|
| 固定审批人 vs 动态审批人 | ❌ **固定写死用户ID** | 动态按"部门负责人/分管领导/人事/财务/金额权限/上一级"等规则自动匹配审批人 | **最大问题**：大单位几十个部门，不可能每个部门手动建4个流程模板写死王科长/赵人事，必须自动找人 |
| 条件分支 | ❌ 无固定规则（只串行） | 如请假天数>3天加分管领导审批、报销金额>5000元加财务总监审批、金额>10万加局长审批 | 大单位审批链必须分级 |
| 会签/加签/转签 | ❌ 无 | 多个审批人同时审批（会签全部同意才过）、临时加审批人、审批人没空转给他人审批 | |
| 退回/驳回 | ⚠️ 只有拒绝，流程结束 | 可退回到"发起人修改后重新提交"，不需要重新发起 | 常用场景，不然一个错字就要重走全流程 |
| 撤回/补正 | ⚠️ 有撤回，但只在审批前 | 发起人在未审批完撤回；审批人点"补正材料"退回 | |
| 抄送人/知会人 | ❌ 无 | 审批通过或某节点时，自动抄送给相关人（知会，不用审批） | 比如请假审批抄送给考勤员 |
| 委托/代理审批 | ❌ 无 | 审批人出差期间可设置代理人，自动把待办转给代理人处理 | |
| 催办/督办 | ❌ 无 | 发起人可一键催办；超过X天未审批自动短信/站内信提醒审批人 | 大单位审批慢是常见痛点 |
| 审批意见附件 | ❌ 无 | 审批人可上传附件（比如签字扫描件、财务票据） | |
| 电子签章/手写签名 | ❌ 无 | 对接Ukey电子签章、手写板签名 | 合同/公文等正式审批需要 |
| 审批痕迹/防篡改 | ❌ 无 | 审批意见+时间戳+数字签名哈希，不可修改，可导出PDF留档 | 合规审计必备 |
| 流程版本 | ❌ 无 | 流程模板修改后，已发起的旧流程用旧版本，新发起的用新版本 | 修改模板不能影响正在跑的流程 |
| 流程委托转接 | ❌ 无 | 审批人没空可以把单据转交给另一个人审批，记录转交关系 | |
| 并行业务审批链 | ❌ 只有串行 | 如"部门负责人"和"直属上级"并行审批完才到下一个节点 | |
| 流程查询/统计 | ❌ 只有列表 | 按部门/时间/类型统计处理时长、平均审批天数、最长待办人 | 用于考核审批效率 |
| 流程模板设计器 | ❌ 只有代码里写死的4个模板 | 图形化拖拽配置：节点类型、审批人规则、条件分支、表单字段 | 大单位不可能每次改流程都找开发 |

### 2.7 数据权限与多单位管理（大单位是否不乱）

|------|------|--------------|----------|

| 操作留痕 | ⚠️ 有OperationLog，但未覆盖所有模块 | 所有写操作(新增/修改/删除)必须记录，导出/批量操作也必须记录 | |

### 2.9 技术与架构保障（大型系统稳不稳）

| 功能 | 现有 | 成熟系统标准 | 差距说明 |
|------|------|--------------|----------|
| 数据库 | ⚠️ SQLite | 生产环境PostgreSQL/MySQL；读写分离 | SQLite只适合单机，多并发就坏 |
| 缓存 | ❌ 无Redis | 字典/权限/单位树/验证码放缓存 | 每次查权限查库太慢 |
| 文件/附件存储 | ❌ 无 | 本地目录/MinIO/阿里云OSS；文件访问权限；病毒扫描；附件大小限制 | 扫描件上传是刚需 |
| 代码审计/漏洞 | ❌ 无扫描 | 每季度安全扫描；SQL注入/XSS/CSRF防护 | 大单位必须过等保2.0三级 |
| 接口文档 & 前后端一致 | ⚠️ 有Swagger | 接口版本号；前端请求统一错误处理；API安全审计 | |
| 定时任务 | ❌ 无 | 用Celery/APScheduler跑：合同到期提醒、年假余额结转、月度报表、超时自动审批 | |
| 移动端H5/小程序 | ❌ 无（纯PC） | 手机浏览器、企业微信、钉钉小程序、独立APP | 审批人不在电脑前必须能手机批 |
| 系统日志/监控 | ❌ 无 | 服务健康检查、接口响应时间、慢查询日志、错误告警邮件 | |
| 数据备份/灾备 | ❌ 无 | 每日自动完整备份；数据库异地备份；一键回滚 | 数据丢失是严重事故 |
| 等保合规性 | ❌ 大量未满足 | 等保三级至少：双因素登录、操作日志保留半年、敏感数据加密、HTTPS、堡垒机 | 政务单位必须过等保 |

### 2.10 一些"细节但影响严谨性"的遗漏

- **身份证号唯一性校验**：跨单位重复身份证？（同一人两个账号）
- **人员离职后账号的归属**：离职后自动停用、工作交接、名下资产自动提醒归还
- **并发修改冲突**：两个人同时编辑同一份人员档案会不会覆盖？
- **导入Excel的数据校验**：身份证校验位错误、性别和身份证不匹配、年龄和出生日期不匹配时自动警告
- **删除操作是硬删除还是软删除**：必须软删除（is_deleted），审计需要保留
- **所有关键字段的修改记录**：ChangeLog目前记录了，但是否包含"修改前值JSON+修改后值JSON"？
- **审批流的并发问题**：两个审批人同时点同意会不会重复推进节点？

## 三、分阶段建设规划（建议按优先级执行）

### 第一阶段：安全与严谨性加固（2-3周，必须先做）

目标：**堵住最大漏洞，保证大单位基本能安全跑起来**

| 编号 | 功能 | 说明 | 紧迫度 |
|------|------|------|--------|
| 1-1 | **审批人动态化** | 流程模板不再写死用户ID，改成"按部门负责人/分管领导/人事岗位/财务岗位"自动匹配；加Person.manager_id字段 | ⭐⭐⭐⭐⭐ 必须 |
| 1-2 | **部门多级树+分管领导** | Department加parent_id/order/manager_id/leader_id；支持拖拽排序 | ⭐⭐⭐⭐⭐ 必须 |
| 1-3 | **请假余额关联** | 建年度假期余额表；请假通过后自动扣余额；余额不足不能提交 | ⭐⭐⭐⭐⭐ 必须 |
| 1-4 | **登录安全加固** | 密码强度校验(8位+组合)、5次失败锁定、登录日志表、Token自动失效、密码90天过期提醒 | ⭐⭐⭐⭐⭐ 必须 |
| 1-5 | **操作审计加强** | OperationLog补充：操作者IP、变更前后JSON；敏感查看（查身份证完整号）也记录 | ⭐⭐⭐⭐⭐ 必须 |
| 1-6 | **软删除+回收站** | 所有删除is_deleted软删，可在回收站恢复；避免手滑删错找不回 | ⭐⭐⭐⭐ 高 |
| 1-7 | **消息推送引擎** | 站内信 + 待办自动通知审批人；流程状态变更通知发起人 | ⭐⭐⭐⭐ 高 |
| 1-8 | **隐私协议/首次使用弹窗** | 用户协议+隐私政策勾选，记录同意时间 | ⭐⭐⭐ 中（合规要求） |
| 1-9 | **并发冲突锁** | 关键接口加乐观锁（version字段）或悲观锁；审批节点原子推进 | ⭐⭐⭐⭐ 高 |

## 四、对照成熟系统的差异总结

| 维度 | 我们的系统（现状） | 成熟系统（如泛微/北森） | 能否短期赶上 |
|------|-------------------|------------------------|-------------|
| 基本CRUD功能 | ✅ 齐全 | ✅ 齐全但更细分 | 已达80% |
| 审批链灵活度 | ⚠️ 写死用户ID，串行 | ✅ 动态审批+条件+会签+退回 | ❌ 差很远，要花1-2个月重构流程引擎 |
| 人事业务闭环 | ⚠️ 只有静态档案 | ✅ 招聘入职/转正/调岗/离职/退休/合同全流程 | ❌ 还差一整套业务链，2-3个月 |
| 行政办公 | ❌ 基本没有 | ✅ 公文/会议/资产/接待/印章/用车 | ❌ 差很多模块 |
| 安全性 | ⚠️ 基础登录 | ✅ 强密码/锁定/SSO/2FA/操作审计 | ⚠️ 1个月可加固到位 |
| 消息触达 | ❌ 站内看 | ✅ 多通道推送 | ⚠️ 2周可加消息队列 |
| 数据严谨性 | ⚠️ 软删除、审计日志不完整 | ✅ 软删+变更历史+审计追溯 | ⚠️ 2周可补 |
| 移动端 | ❌ 无 | ✅ H5/小程序/APP全支持 | ❌ 至少需要1-2个月做H5 |
| 大数据量性能 | ⚠️ SQLite不支持50人以上并发 | ✅ 万级用户+读写分离+缓存 | ❌ 必须换数据库+加缓存 |
| 等保合规 | ❌ 基本不满足 | ✅ 通过等保三级 | ❌ 需要1-2个月专项改造 |

## 五、给您的最终建议

**如果明天就要给全单位正式用**：优先做第一阶段（安全+流程加固），不然遇到下面的问题会很狼狈：
1. 有10个部门，但4个流程模板写死了王科长审批，其他9个部门没审批人
2. 有人拿身份证后6位弱密码，被其他人登录查看全部人事档案
3. 请假10天再请假10天，没有余额控制，假就白请了
4. 手删了一份人员档案，找不回来，也查不到是谁删的

**第一阶段做完再用3个月**：做第二阶段HR闭环。此时人事部门会觉得"这个系统真的帮我干活了"，而不只是"放档案的地方"。

**再用半年**：做第三阶段行政办公，让每个部门都能在上面办公（不再只有人事用）。此时系统才真正称得上是"单位内部信息管理系统"，而不是"人事档案系统"。

**最后**：考虑移动端+钉钉/企业微信集成+数据库升级+等保。

## 六、建议的建设时间线（总约6-8个月）

```
第1-3周   →  第一阶段：安全+流程+审批人重构（做完敢上线）
第4-9周   →  第二阶段：HR业务闭环（做完人事满意）
第10-17周 →  第三阶段：行政办公模块（做完大家都用）
第18-24周 →  第四阶段：移动端+数据库迁移+集成（做完是成熟系统）
```

按照这个节奏走，**3个月后可以正式给大单位用**，严谨性和合规性基本到位；6-8个月后可对标中小型的泛微/用友版本。
